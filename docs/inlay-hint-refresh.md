# 输入时内联提示闪动回归

## 根因

此前 `EditorState.applyTextBufferChange()` 每次编辑都会调用 `clearInlayHints()`。
宿主等待防抖和 LSP 响应后才重新发布提示。这会反复删除、恢复所有提示的虚拟宽度，
即使只在文件底部输入，也会影响顶部正文的位置和软换行布局。普通 Canvas 重绘不是该闪动的根因。

## 处理约定

- 本地编辑保留未受影响行的提示，保守失效编辑范围覆盖的行，并按 `TextChange.lineDelta` 移动后续提示。
- 提示内容/坐标未变时，仅推进锚点文档版本，保留原集合和布局版本；复用已有行布局缓存及软换行增量更新。
- 保留的是等待 LSP 重新确认的显示结果，不保证旧标签在语义上仍然最新。有效响应仍会替换请求范围内的提示，空响应会删除对应提示。
- 过期响应仍由 `replaceInlayHintsInLines()` 的文档版本检查拒绝；禁用提示/断开服务时仍可显式清空。
- 重定位以每条变更的 `documentVersion` 为准，不能把批量变更中的第一条直接提升到 buffer 最终版本。
- 发现版本断档时清空，避免错误坐标；已经被更新响应覆盖的旧事件不能重复移动提示。
- 提示按行有序保存；在全部提示之后输入时，无需复制提示集合或递增提示布局版本。

## 自动回归

在 editor-kit 根目录执行：

```bash
./gradlew :core:editor-view:testDebugUnitTest --tests '*EditorStateInlayHintsTest' --tests '*EditorInlayHintLayoutTest' --no-daemon --console=plain
```

覆盖底部连续输入、编辑行局部失效、插入/删除换行、多行替换、延迟事件批次、版本断档、
旧响应拒绝、当前响应抢先到达、空响应及显式关闭提示。
布局回归检查顶部提示占位、软换行行数，以及输入前后 prefix layout 的实例复用，而不只检查提示数据。

## 真机验收

1. 打开启用了 clangd 内联提示的 C/C++ 文件，保持顶部提示可见，在下方连续输入与退格。
2. 顶部提示应持续显示，旁边代码不能反复左右移动；分别开启和关闭软换行验证。
3. 在提示前插入/删除整行，确认后续未编辑行的提示随文本移动。
4. 修改有提示的那一行时，允许该行提示暂时失效；停止输入后应以新 LSP 结果更新。
5. 切换文件、关闭提示、断开 LSP 后确认旧提示不会残留或被延迟响应恢复。

自动测试覆盖状态与布局；真实服务响应时序和设备观感仍需上述装机验证。
